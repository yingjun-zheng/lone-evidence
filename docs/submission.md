## B. 实现方式（约 500 字，主字段用这个）

**一句话**：把「一次搜索」变成「一次对照实验」，用元宝搜索的参数化检索能力，把一条说法剥到只剩真正独立的发声者。

**核心方法：四步取证，每步都是一次独立的 API 调用。**

1. **原始检索** `Mode=2, Cnt=50` —— 看清传播规模，拿到 50 条结果与域名分布。
2. **同源聚类** —— 对标题做指纹化（去站点后缀、只保留汉字数字，转字符 2-gram 做 Jaccard 相似度），用并查集把高相似的合并成簇。一簇 = 同一篇通稿被转载多次。
3. **剥离重搜** `Site=exclude:top5域名` —— 找出占比最高的 5 个域名，把它们全部排除后**再搜一次**。去掉复读机之后还在说这件事的，才算旁证。若前 5 名覆盖率不足 40%，说明传播本身已分散，引擎会跳过这一步并如实说明。
4. **官方口径** `Industry=gov` —— 定向召回政府与学术源，再用 `.gov.cn` / `.edu.cn` 后缀做硬判断，剔除跑题文章。

**结论 = 传播结构 × 立场。** 结构给出「几个独立声音 + 有没有官方口径」，立场给出「这些声音在支持还是在否认」。六种结论：查无此事 / 孤证 / 多源否认 / 多源一致否认 / 多源警示 / 多源一致警示 / 多源讨论。

**立场判定做了两层。** 第一层是句式启发式（明确否定词 + 疑问句式），先在页面上给出初判；第二层调用云端大模型（`deepseek-v4.1-flash`，抽样 18 条标题）做语义复核。两者不一致时，**以模型为准并回写大结论**，同时在界面上标明「已按 AI 复核修正」——分歧本身就是要给人看的信息。

**为什么离不开元宝搜索**：第 3 步的 `Site=exclude:` 排除重搜、第 4 步的 `Industry=gov` 垂直召回，都是 SearchPro 独有的参数能力。换成普通搜索接口，这套方法论不成立。

**技术栈**：Python 3 标准库（零第三方依赖）+ TC3-HMAC-SHA256 自实现签名 + 单页 HTML/原生 JS + WorkBuddy 云服务 LLM（CDN SDK，免密钥）。一次完整取证 3 次调用，相同参数命中本地缓存不扣额度，额度有台账。

## F. 一句话讲清"哪里不一样"（问答备用）

> 别人做的是「搜到 → 总结 → 给你答案」，我做的是「搜到 → 归类 → **把最吵的排除掉再搜一次** → 看还剩谁」。
> 前者回答"网上怎么说"，后者回答"**到底几个人在说**"。这是两个不同的问题。
