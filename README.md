# 孤证 · Single Source

> 43 个来源，1 个声音。

**搜索结果的数量，不等于信源的数量。**

一个查证引擎：把「一次搜索」变成「一次对照实验」。用元宝搜索 SearchPro 的参数化检索能力，
把一句说法剥到只剩真正独立的发声者。

---

## 为什么不是又一个"AI 辟谣工具"

| 常见做法 | 本项目的做法 |
|---|---|
| 搜一次，把 10 条结果丢给模型总结 | 四次参数不同的检索，做对照 |
| 「有 43 条结果」= 证据充分 | 43 条可能只出自 1 个人 |
| 输出一段话，无法验证 | 输出可复算的数字（独立簇数、覆盖率、权威度） |
| 查不到就编一个合理答案 | 查不到就说「查无此事」，并列出查了什么 |

关键在**剥离重搜**：找出占比最高的域名，用 `Site=exclude:` 全部排除后再搜一次。
去掉复读机之后还在说这件事的，才算旁证。

---

## 四步取证

```
① 原始检索   Mode=2  Cnt=50                    看清规模
② 同源聚类   标题指纹(字符2-gram Jaccard)        认出同一篇通稿被转载
③ 剥离重搜   Site=exclude:top5域                去掉复读机还剩谁
④ 官方口径   Industry=gov                       政府源里有没有这句话
```

每一步都依赖 SearchPro 的自有字段（`Mode` / `Site` / `Cnt` / `Industry` / `Freshness`），
换成普通搜索接口这套方法不成立。

> 注：`authority_level`（0–5 权威度）**仅旗舰版返回**。标准版下本引擎自动降级为
> 「`Industry=gov` 召回 + `.gov.cn`/`.edu.cn` 域名硬判断」，功能不受影响。

### 判定：结构 × 立场

| 独立信源 | 立场 | 结论 |
|---|---|---|
| 0 | 任意 | 查无此事 |
| ≤1 | 任意 | 孤证 |
| ≥2 | 多数否认 + 有官方口径 | 多源一致否认 |
| ≥2 | 多数否认 | 多源否认 |
| ≥2 | 多数警示 + 有官方口径 | 多源一致警示 |
| ≥2 | 多数警示 | 多源警示 |
| ≥2 | 混杂 | 多源讨论 |

**立场是启发式提示，不是判定。** 详见下方「诚实的边界」。

## 跑起来

```bash
cd src
python server.py          # 打开 http://127.0.0.1:7788
```

零第三方依赖，纯标准库。端口用 7788 是为了避开本地 Nacos 的 8848。

### 凭证

```bash
cp .env.example .env
# 填入腾讯云 API 密钥对（不是只有 ID）
#   WSA_SECRET_ID=AKID...
#   WSA_SECRET_KEY=...
```

SecretId 与 SecretKey 必须成对。只有 `AKID` 开头的 ID 无法签名。

### 自检

```bash
python check.py     # 验证签名 + 打印返回字段实况，只花 1 次额度
```

## 额度

`data/quota.json` 记账，`/api/quota` 可查。一次完整取证 = 3 次调用，
相同参数命中 `data/cache/` 不重复扣额度。6000 次 ≈ 2000 次查证。

## 云服务接入

立场判定除启发式外，再用 WorkBuddy 云服务的 LLM 模块做一次语义复核（免密钥，前端直调）：

| 项 | 取值 |
|---|---|
| SDK | CDN `@tencent-ai/workbuddy-cloud-sdk@dev` |
| 初始化 | `endpoint` + `publishableKey`（均来自 publicConfig，不硬编码 endpoint 字面量） |
| 模型 | 优先 `deepseek-v4.1-flash`，回退 `glm-5.3-flash` / `hunyuan-chat` |
| 输入 | 标题抽样 18 条（全量 50 条会把延迟拉到数十秒） |
| 流式 | 该 API 只支持 `stream: true`，非流式会直接报 `request_stream_required` |
| 超时 | 25 秒 abort，按 `error.code` 前缀分支提示 |

**不要用默认的 `auto` 模型。** 实测同一输入 `auto` 耗时 27–82 秒（会路由到思考模型），
而 `deepseek-v4.1-flash` 为 2.3 秒。交互式场景里默认模型是个陷阱。

复核结果与启发式并列展示，并标注“一致 / 不一致”——两个独立方法都指向同一结论时，
这个结论才值得报给用户。

## 诚实的边界

- **独立信源 ≠ 事实为真。** 独立只说明「有多个人在独立地说」，不说明说得对。
- **立场是启发式，不是语义理解。** 本引擎靠标题句式（明确否定词 + 疑问句）粗判，
  在实测中会把「保温杯不能装牛奶」这类大量中性表述的话题判成「立场混杂」。
  界面明确标注了这一点，并给出原文链接。
- **词表法已实测失败。** 辟谣文里同样大量出现「危害」「风险」「有毒」，
  主题词与判据词在字面层面无法分离，因此没有采用词频投票。
- **剥离只排除 top5 域名。** 若前 5 名覆盖率低于 40%，说明传播本身已分散，
  引擎会跳过剥离并退回原始簇数，而不是把结果算成 0。
- **聚类用于识别转载，不用于判断议题。** 中文标题改写幅度大，字符相似度抓不住
  「同一议题的不同措辞」，只对「同一篇通稿的转载」有效。
- **离线演示数据一律标注。** 没有真实调用时，页面顶部会明写「未调用元宝搜索」。

## 合规

不涉及时政与个人信息。演示选题限于生活、消费、科普类公开说法。
不含任何真实密钥（`.env` 不入库），不含他人个人信息。

数据来源：元宝搜索（Tencent Yuanbao Search, wsa）
